## 1. 它是做什么的

美术从 Maya / 3ds Max / Blender 导出的 FBX，进 Unity 之后往往带着一堆"看不见的坑"：
面数超标、一个模型挂七八个材质球、层级里全是 `pCube1` `default`、轴心点飞到模型外面几米远、
贴图 8192 不是 2 的幂……这些问题单看模型看不出来，等打包上机才炸：DrawCall 飙升、内存膨胀、光照烘焙出黑块。

本工具把这些**美术资产规范自动扫一遍**，给你一份带修复建议的问题清单，
并支持一键导出 Excel 交付给美术按行返修。

**核心能力：**

- 🔍 **19 类问题自动检测**：网格、材质、贴图、UV、命名、变换、骨骼、轴心全覆盖
- 📊 **场景级效率分析**：材质复用度 + DrawCall 预算反推
- 🎯 **一键定位**：点「定位」直接跳到 Hierarchy 里出问题的那个对象
- 🔎 **严重度 / 类型双维筛选**：先修高风险，再清低优先
- 📗 **Excel 报告导出**：总览统计 + 每种问题一张明细表，带超链接跳转
- 🌓 **明暗主题自适应**：Unity Personal / Pro 皮肤下都能正常显示

## 3. 安装

### 方式 A：复制文件夹（推荐）

1. 把 `ModelChecker-V0.3` 整个文件夹拷进你的 Unity 工程的 `Assets/` 目录下，最终结构为：

```
你的工程/
└── Assets/
    └── ModelChecker-V0.3/
        ├── EPPlus.dll                  # Excel 生成库
        └── Editor/                     # 全部代码（自动编入 Assembly-CSharp-Editor）
            ├── ModelStandardChecker.cs   # 主窗口 · 检查调度 · 导出流程
            ├── ModelChecker.cs           # 全部检测算法
            ├── UIDrawer.cs               # 界面绘制 · 显示名与配色映射
            ├── ReportExporter.cs         # Excel 报告生成
            └── DataModels.cs             # 配置类 · 问题模型 · 枚举
```

2. 切回 Unity，等待编译完成（首次约 5–15 秒，视工程大小而定）。
3. 打开菜单栏 `工具 → 模型规范检查器`，窗口正常弹出即安装成功。

### 方式 B：从 GitHub Clone

```bash
git clone <本仓库地址>
```

把 clone 下来的 `Assets/ModelChecker-V0.3` 拷进目标工程即可。

### 可选优化：让 `EPPlus.dll` 不进包体

`EPPlus.dll` 目前放在 `Editor/` **之外**，Unity 会把它当成运行时插件、打进最终包体。
如果在意包体大小，二选一：

- 把 `EPPlus.dll` 移动到 `Editor/` 目录内；或
- 选中 `EPPlus.dll`，在 Inspector 的 **Platform Settings** 里取消勾选所有平台、只保留 **Editor**。

> 不做这一步工具也能正常用，只是包体会多个几 MB。

### 卸载

直接删除 `Assets/ModelChecker-V0.3` 文件夹即可，不残留任何配置文件。

## 6. 检查配置详解

展开「检查配置」后分两块：**阈值**（数值）与 **检查项**（开关）。
每个数值字段右侧都有一个 **`R`** 小按钮，点一下恢复该项默认值；所有字段都有鼠标悬停提示。

### 6.1 阈值

| 字段 | 默认值 | 含义 |
|---|---|---|
| **最大三角面数** | 10000 | 单个网格超过这个三角面数就报「三角面数」问题 |
| **最大材质数** | 2 | 单个 Renderer 的材质槽超过这个数量就报「材质数量」问题 |
| **最大骨骼数** | 60 | 单个蒙皮网格的骨骼数上限 |
| **最大贴图尺寸** | 4096 | 贴图宽或高超过这个像素值即报「贴图尺寸」问题 |
| **轴心偏移容差** | 1.0 | 单位：米。轴心点到网格包围盒的距离超过此值即判为轴心跑飞 |
| **UV拉伸比阈值** | 5.0 | 三角形在 3D 空间与 UV 空间的面积比超过此值即报「UV拉伸」 |
| **DrawCall 预算** | 200 / 700 | 最小 / 最大 DrawCall 预算区间，用于反推「平均每材质该扛多少面」 |
| **每页显示数量** | 10 | 结果表格每页条数，有效范围 **5 – 200**（超出会被自动收敛） |

> 📌 **配置不会保存**。关掉窗口或重启 Unity 会恢复全部默认值。
> 建议把团队统一规范记在文档里，每次按需调整；或直接改 `Editor/DataModels.cs` 里的 `ModelCheckConfig` 默认值。

### 6.2 检查项开关

| 开关 | 默认 | 说明 |
|---|---|---|
| 检查子节点命名 | ✅ 开 | 递归检查整棵子树的命名是否用了默认名 |
| 检查轴心偏移 | ✅ 开 | 检测模型轴心点是否跑到网格外部 |
| 检查UV重叠 | ⬜ 关 | 检查 UV 坐标是否越出 0–1 范围 |
| 检查Lightmap UV | ⬜ 关 | 检查是否缺少 UV2（光照贴图通道） |
| 检查材质使用效率 | ✅ 开 | 场景级材质复用度与 DrawCall 预算分析 |
| 检查UV拉伸 | ✅ 开 | 检测 UV 拉伸比与纹素密度是否合理 |

> 💡 **轴心偏移** 和 **UV拉伸** 遍历开销较大（逐顶点 / 逐三角形），
> 大场景（几十万面以上）检查会明显变慢。赶时间可临时关掉这两项。

## 7. 检查项详解

### 7.1 网格与结构

| 检查项 | 触发条件 | 严重度 | 修复建议 |
|---|---|---|---|
| **三角面数** | 三角面数 > 最大三角面数（默认 10000） | 🔴 高 | 在建模软件中减面，删除看不见的细节，优化模型结构 |
| **网格拓扑** | 顶点数为 0，或索引数不能被 3 整除 | 🟡 中 | 重新导出模型确保数据完整；导出前先做三角化处理 |
| **命名规范** | 名称命中了默认名关键词（见下） | 🟢 建议 | 用有意义的名字：静态物体 `SM_模型名_01`，动态物体 `DM_模型名_01` |
| **变换设置** | `localScale` 不等于 (1,1,1) | 🟡 中 | 导出前重置缩放为 1（冻结变换） |
| **空节点** | 该对象有子节点，但身上只挂了 `Transform` | 🟡 中 | 删除不必要的空节点，简化层级 |
| **导入设置** | 模型的 `Read/Write Enable` 处于开启状态 | 🟡 中 | 如非必要关掉 Read/Write Enable，省一份内存拷贝 |
| **骨骼数量** | 蒙皮网格骨骼数 > 最大骨骼数（默认 60） | 🔴 高 | 优化骨骼结构，删除不必要的骨骼 |
| **骨骼丢失** | `bones` 数组里存在 `null` 引用 | 🟡 中 | 重新绑定骨骼或重新导入模型 |

**默认命名关键词黑名单**（命中任意一个即报警）：

```
pCube  Cube  default  GameObject  polySurface  pasted
pCylinder  pSphere  pCone  pTorus  pPlane  pDisc
```

> 子节点递归检查时只匹配 `pCube` 和 `default` 两个关键词。

### 7.2 材质与贴图

| 检查项 | 触发条件 | 严重度 | 修复建议 |
|---|---|---|---|
| **材质数量**<br>（界面显示为「含有多维材质物体」） | 材质槽数量 > 最大材质数（默认 2） | 🟡 中 | 合并材质，或改用贴图 / 图集 |
| **材质丢失** | 材质数组里存在 `null` 元素 | 🟡 中 | 重新指定正确的材质球 |
| **贴图尺寸** | 贴图宽或高 > 最大贴图尺寸（默认 4096） | 🟡 中 | 用图像软件降到 1024 / 2048 |
| **贴图规格** | 贴图宽或高不是 2 的幂 | 🟡 中 | 调整为 512 / 1024 / 2048 等 2 的幂尺寸 |
| **贴图导入** | 法线贴图的 Texture Type 不是 `Normal Map` | 🟡 中 | 在贴图导入设置里把 Texture Type 改为 Normal Map |
| **材质使用效率** | 见下方三条规则 | 🟡 中 | 合并相似材质、使用纹理图集 |

**检查范围**：材质的**主贴图**（`_MainTex`）与**法线贴图**（`_BumpMap`）。
同一张贴图全局只报一次——多个模型共用一张超标贴图时，不会重复刷屏。

#### 材质使用效率（场景级分析）

这是唯一一类**不针对单个对象、而针对整个场景**的分析（列表中显示为「无对象」）。
它统计：场景三角面总数、去重材质球总数、材质指派总次数、平均每材质负责面数，
再用 DrawCall 预算反推两条参考线：

```
minTrianglesPerDC = 场景总面数 / 最大DrawCall预算(700)   ← 若只允许 700 DC，每个 DC 至少该扛多少面
maxTrianglesPerDC = 场景总面数 / 最小DrawCall预算(200)   ← 若只允许 200 DC，每个 DC 要扛多少面
```

| 判定 | 结论 |
|---|---|
| 平均面数 **<** `minTrianglesPerDC` | 材质使用效率偏低：材质球过多，DrawCall 可能超限 → 建议合并材质 / 用图集 |
| 平均面数 **>** `maxTrianglesPerDC × 2` | 材质复用度过高：可能缺乏视觉细节 → 建议增加贴图变化，或检查是否有不必要的高面数模型 |
| 只被使用 **1 次**的材质占比 **> 30%** | 大量材质只被用一次，产生不必要的 DrawCall → 建议合并或改用图集 |

> 分析过程的完整数据会输出到 Unity Console，便于二次排查。

### 7.3 UV 与轴心

| 检查项 | 触发条件 | 严重度 | 修复建议 |
|---|---|---|---|
| **UV映射** | 网格缺少 UV0 通道 | 🟡 中 | 在建模软件中创建 UV 映射 |
| **UV映射**（越界） | 有 UV 分量超出 0–1 范围（需开启「检查UV重叠」） | 🟡 中 | 调整 UV 布局，确保全部落在 0–1 内 |
| **光照贴图UV** | 缺少 UV2 通道（需开启「检查Lightmap UV」） | 🟡 中 | 在模型导入设置中勾选 Generate Lightmap UVs |
| **UV拉伸** | 最大拉伸比 > UV拉伸比阈值（默认 5） | 🟡 中 | 见下方分级建议 |
| **轴心偏移** | 轴心点到包围盒距离 > 容差（默认 1 米） | 🟡 中 | 在建模软件中把轴心点移回模型网格内部 |

> ⚠️ 缺少 UV0 时会直接结束该模型的 UV 检查，不再继续判断 UV2 / 越界 / 拉伸——先把 UV 建出来。

#### UV 拉伸比怎么算

逐个三角形比较它在**世界空间**的面积与在 **UV 空间**的面积：

```
stretchRatio = max(3D面积 / UV面积, UV面积 / 3D面积)     ← 双向取大，拉伸和压缩都能抓到
```

取全部三角形中的最大值作为该模型的拉伸比。同时估算**纹素密度**：

```
texelDensity = Σ(UV面积 × 贴图宽 × 贴图高) / Σ(世界面积)     ← 单位：像素/平方米
```

**分级建议：**

| 条件 | 建议文案 |
|---|---|
| 拉伸比 > 10 | UV 拉伸严重，建议重新展开 UV |
| 密度 < 50 | 贴图密度过低，建议细分 UV 或提高清晰度 |
| 密度 > 1000 | 贴图密度过高，建议降低贴图分辨率 |
| 其他 | UV 拉伸在可接受范围内 |

#### 轴心偏移怎么算

```
pivot     = (0, 0, 0)                  ← 轴心即网格本地原点
closest   = bounds.ClosestPoint(pivot) ← 包围盒上离轴心最近的点
distance  = |pivot - closest|
if (distance > 容差) → 判定为轴心跑飞
```

结果按偏移距离**从大到小**排序，偏得最狠的排在最前面，方便优先处理。
列表和 Excel 报告里都会展开显示「世界坐标 / 偏移向量 / 偏移距离」三个数据。

## 8. 严重度分级

| 等级 | 颜色 | 包含的问题类型 |
|---|---|---|
| 🔴 **高** | 红 | 三角面数、骨骼数量 |
| 🟡 **中** | 橙 | 材质数量、贴图尺寸、材质使用效率、材质丢失，以及其余大部分类型（变换设置、空节点、网格拓扑、贴图规格、贴图导入、UV映射、光照贴图UV、导入设置、骨骼丢失、轴心偏移、UV拉伸） |
| 🔵 **低** | 蓝 | （当前无类型归入此级） |
| 🟢 **建议** | 绿 | 命名规范 |

> 严重度只影响**列表排序和筛选**，不改变任何检测结果。
> 结果列表默认按「高 → 中 → 低 → 建议」排序。

## 9. 筛选、分页与定位

### 9.1 按严重度筛选

点左侧摘要栏「**严重度 · 点击筛选**」下的任意一行（高 / 中 / 低 / 建议），表格立即只显示该等级的问题。
**再点同一行可取消筛选**。

### 9.2 按问题类型筛选

点「**问题类型 · 点击筛选**」下的任意一行，表格只显示该类型的问题。**再点同一行取消筛选**。

> 🔑 **两个筛选是互斥的**：
> 点严重度会自动清除已选的问题类型，点问题类型会自动清除已选的严重度。
> 这样避免了「高 + 三角面数」双重叠加后表格空掉、让人以为没问题的困惑。
>
> 筛选条件变化时会自动回到第 1 页并把表格滚回顶部。
> 想一次性恢复全部结果，点表格右上方的 **[清除筛选]** 按钮。

### 9.3 分页

结果表格底部是分页条：

```
第 1-10 条 / 共 128 条            [上一页]   1 / 13   [下一页]
```

**每页条数**可以在两处修改，改哪个都一样（同一份数据）：

1. 表格右上方的 `每页 [__] 条` 输入框，或
2. 「检查配置」面板里的 **每页显示数量**

有效范围 **5 – 200**，超出会自动收敛到边界值。

### 9.4 定位到场景对象

每条问题最右侧都有一个 **[定位]** 按钮（前提是该问题能对应到具体对象）：

- 点击后，Unity 会**选中**该对象并在 Hierarchy 中**高亮闪烁**
- 场景级问题（材质使用效率）没有具体对象，此处显示「无对象」，不可点击

## 10. 导出 Excel 报告

点击顶部 **[导出报告]**（需先有检查结果）→ 弹出保存对话框 →
默认文件名 `模型检查报告.xlsx`、默认位置为工程的 `Assets/` 目录 →
生成完成后会自动用系统默认程序（Excel / WPS 等）打开。

### 10.1 报告结构

**Sheet 1「总览统计」**

| 区块 | 内容 |
|---|---|
| 报告头 | `Unity 模型规范检查报告` + 生成时间 |
| 基础统计信息 | 总问题数、问题分类数、涉及模型数、总三角面数、总游戏对象 |
| 问题类型分布 | 三列表格：问题类型 · 数量 · 占比%，按数量降序 |

> 🔗 总览表里的**问题类型名是超链接**，点一下直接跳到对应的明细表。

**Sheet 2…N「各问题类型明细」**（每种出现过的问题类型一张表）

| 位置 | 内容 |
|---|---|
| 第 1 行 | `问题类型：XXX` |
| 第 2 行 | 问题数量 |
| 第 3 行 | 生成时间 |
| 第 5 行 | 表头：模型名称 · 问题描述 · 建议修复<br>**轴心偏移额外追加**：当前位置 · 偏移向量 · 偏移距离 |
| 第 6 行起 | 数据行 |

所有明细表都：表头加粗居中带边框、数据行 10 号字、冻结前 5 行（表头常驻）、列宽自适应。

### 10.2 文件被占用怎么办

如果目标 xlsx 已经被 Excel 打开，工具会检测到占用并提示：

- **「是否关闭所有 Excel 窗口？」** → 选「是」：工具会尝试关闭 Excel 进程再写入
- 选「否」：提示你手动关闭后重试

> ⚠️ 选「是」时关闭的是**你当前打开的所有 Excel 工作簿**。如果有其他未保存的文件正在编辑，
> 建议先手动保存并关闭，再回来重新导出。更稳妥的做法是导出时**换一个新文件名**。

## 11. 常见问题 FAQ

**Q：菜单栏里找不到「工具 → 模型规范检查器」？**

按顺序排查：
1. 控制台是否有编译错误（红色报错）？有错则整个编辑器程序集都不编译，菜单不会出现，先修错。
2. `Editor` 文件夹是否真的在 `Assets/` 下面？放错位置不会被编译。
3. 试试 `Assets → Refresh`（快捷键 `Ctrl/Cmd + R`）强制刷新一次。

**Q：检查跑完了，但一条问题都没有？**

- 确认「检查范围」是**当前打开的场景**——工具不扫描 Project 面板里的 FBX 资源，只扫描场景里已经摆放的实例。
- 只统计**激活状态**的对象；场景里未勾选的对象不会被扫描。
- 也可能是场景确实很干净，或者阈值放得太宽松。

**Q：为什么改了配置，重开窗口又变回默认值了？**

这是当前版本的已知行为：配置只保存在内存里，**没有落盘**。详见 [第 12 节](#12-已知限制)。

**Q：大场景检查时 Unity 卡住了？**

轴心偏移和 UV 拉伸两项是逐顶点 / 逐三角形遍历，几十万面以上的场景会比较慢。
临时关掉这两项开关即可显著提速。检查期间有进度条，耐心等待即可。

**Q：导出的报告打不开 / 提示文件损坏？**

一般是导出时文件被占用导致写入不完整。关掉报告文件后重新导出一次；
仍不行就换个文件名、换个目录再试。

**Q：支持批量检查多个场景 / 预制体吗？**

当前版本只检查**当前激活场景**。多场景请逐个打开后分别检查。

**Q：「材质数量」这条为什么显示成「含有多维材质物体」？**

这是界面上的既有措辞，指的确实是"材质槽数量超标的物体"，含义不受影响（后续版本会统一文案）。

## 12. 已知限制

| # | 限制 | 说明 |
|---|---|---|
| 1 | **配置不持久化** | 未接入 `EditorPrefs` / `ScriptableObject`，重开窗口即恢复默认。团队规范建议直接改 `DataModels.cs` 里的默认值 |
| 2 | **只检查当前场景** | 不扫描 Project 面板里的资源文件，也不支持多场景批量 |
| 3 | **只统计激活对象** | 场景中被禁用（未勾选）的对象不会被扫描 |
| 4 | **动画设置未启用** | 代码中保留了 `动画设置` 分类，但检测逻辑尚未实现，暂不会产生任何问题 |
| 5 | **蒙皮网格的纹素密度不准** | UV 拉伸检测在估算纹素密度时只读取静态网格的材质，蒙皮网格得到的密度值恒为 0，分级建议中的"密度"判断对蒙皮模型失真；**拉伸比本身仍然有效** |
| 6 | **大场景性能** | UV 拉伸为逐三角形全量遍历，高面数模型单次检测较慢，建议按需关闭 |
| 7 | **`EPPlus.dll` 会进包体** | 该 DLL 位于 `Editor/` 之外，会被当作运行时插件打进玩家包。处理方式见 [3. 安装 · 可选优化](#3-安装) |

## 13. 推荐工作流

**美术同学（返修方）**

```
收到 模型检查报告.xlsx  →  打开「总览统计」看问题分布
→  按占比最高的类型优先处理，点类型名跳到明细表
→  按「建议修复」列逐条改模型  →  改完交给 TA 复检
```

**TA / 技术美术（验收方）**

```
① 拿一份干净的场景 → 用默认阈值跑一遍，确定团队基线
② 把这套基线阈值写进团队规范文档（当前版本配置不落盘，需手动同步）
③ 每次美术提交模型后：
   打开对应场景 → 工具 → 开始检查
   → 先看「严重度 · 高」（面数 / 骨骼），这类直接影响性能，必须清零
   → 再看「材质使用效率」的场景级结论，评估 DrawCall 风险
   → 低优先项（命名、变换）可以按迭代节奏分批清理
④ 导出报告归档，作为本次提交的资产体检记录
```

**经验阈值参考**

| 场景类型 | 最大三角面数 | 最大材质数 | 最大骨骼数 | 最大贴图 |
|---|---|---|---|---|
| 手游 · 小物件 | 2000 – 5000 | 1 – 2 | 30 | 1024 |
| 手游 · 角色 | 10000 – 20000 | 2 – 3 | 60 – 90 | 2048 |
| 端游 / 主机 · 场景 | 30000 – 50000 | 3 – 5 | 120+ | 2048 – 4096 |

> 上表仅是通用起手值，实际请按项目性能预算与目标机型调整。
